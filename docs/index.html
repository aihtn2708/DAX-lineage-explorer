Lineage for every DAX measure, down to the visuals that use it.

Run EVALUATE INFO.MEASURES() against a Power BI, Fabric or Analysis Services model, export the result to Excel, and drop it here with the report. You get what each measure reads, what reads it, every visual that uses it, and which measures nothing uses at all.

Drop your export and report here

Model: .xlsx, .csv or .json from the INFO.* queries. Report: .pbix, .pbit or a PBIP folder. Drop them together.

Files are read in this browser tab. Nothing is uploaded anywhere. From a .pbix only the report layout and the model's definitions are read, never its data.

Or paste the result grid (copy table from DAX query view)
Tab- or comma-separated, header row first.

1 · Run the queries

  1. Power BI Desktop: DAX query view
  2. Fabric: the semantic model's DAX query editor
  3. DAX Studio, SSMS or Tabular Editor on an XMLA endpoint

Only INFO.MEASURES() is required. Add INFO.COLUMNS() so a bare [Amount] can be told apart from a missing measure.

2 · Export to Excel

  • Paste each result into its own sheet, named INFO.MEASURES, INFO.TABLES, INFO.COLUMNS
  • Or save each as CSV and drop them together
  • Sheet names are optional; the columns give each one away

3 · Add the report (optional)

  • .pbix: report and model in one file, drop it alone. The model's definitions are decompressed here in the browser
  • .pbit (File → Export → Power BI template): the same, smaller
  • PBIP: pick or drop the project folder

"Unused" means unused in the reports you load. Other reports on the same semantic model, Excel, paginated reports and RLS rules are not seen, so check before deleting.
